# Processor format research

Reviewed 2026-10-19. This covers all 113 identities in the local `payment_processor` catalog: three previously researched and 110 searched by three GPT-6 Luna subagents. Five documented rules are enabled.

This is a bounded search of public documentation. An outcome other than supported means **no rule was enabled from the evidence reviewed**, not that the processor can never be recognized. Catalog roles and names were not changed. Source summaries below are paraphrases.

The [complete research records](../data/processor-formats/research.json) retain the per-processor search queries, source URLs, scope, findings and reasons. The [import file](../data/processor-formats/researched.json) contains only validated, enabled rules. See [format workflow](processor-formats.md) for usage.

## Review decisions

- WePay: enabled only the documented `WPY*<merchant>` form.
- Zettle: enabled only `PayPal Point of Sale *<company>`. Generic `PP*` is shared with other PayPal flows, so it cannot identify Zettle. Legacy `IZ *` and `IZETTLE*` were not established by official sources in this pass.
- Shift4: rejected `PF*<merchant>` as a processor identifier because `PF` is generic payment-facilitator notation.
- Paysafe: kept `NBX*DARRELSDONUTS` as an inconclusive lead. Repeated glossary examples do not establish a fixed processor-owned prefix contract.
- Zong: researched the legacy carrier-billing company acquired by eBay/PayPal, excluding the unrelated Pakistani telecom and similarly named sites.

## Coverage after the importer fix

This report records the original 113-identity review. The importer subsequently
expanded its class and label selection, discovering further identities. Square
and PayPal formats have since been researched and added to the import file; see
[the current format workflow](processor-formats.md). Other newly discovered
identities are not yet covered by this research pass. Do not interpret their
absence here as an unsupported-format finding.
